- [x] **Mission 18: Incident Bundle Contract & Preflight Validation** (2026-10-21, implementation complete — local validation only; CI pending)
  - Documented the canonical incident bundle contract derived from existing code (no invented files or fields): the incident directory (named `<incident_id>`) is the only required entry; `logs/application.log`, `metrics/metrics.csv`, `git_diff.patch`, `service/`, and `docker-compose.yml` are all optional; `ground_truth.md` is evaluation-only and never read at runtime.
  - `agents/bundle_validator.py`: deterministic, read-only validator (zero LLM calls, no new dependencies) exposing `validate_incident_bundle()` → `BundleValidationResult` (frozen; severity-tagged `BundleIssue`s with stable codes and actionable `path: detail` messages), `require_valid_incident_bundle()` → raises `FileNotFoundError` / `NotADirectoryError` / `InvalidIncidentBundleError`, and a CLI (`python -m agents.bundle_validator <dir> [--incident-id ID]`, exit 0 valid / 1 invalid). It opens only the two canonical evidence files by relative path and never enumerates the bundle.
  - Fatal conditions: nonexistent path, non-directory path, invalid or mismatched incident ID, symlinked bundle or entry symlink escaping the root, an entry whose type contradicts the contract, a declared channel directory (`logs/`, `metrics/`) whose expected file is absent, a present-but-empty/malformed `metrics/metrics.csv` (messages name the metric and the offending 1-indexed file row), and a present-but-invalid metrics timestamp (an ISO-8601 UTC instant ending in `Z`, e.g. `2026-08-28T14:00:00Z`; code `metrics_timestamp_invalid`).
  - Legitimate partial evidence preserved (explicitly non-fatal): any evidence source absent, empty log file (warning `empty_log_file`), evidence-free bundle (warning `no_evidence_sources`). Existing empty-directory and non-standard-filename fixtures remain valid.
  - Wired into `IncidentOrchestrator._validate_incident_dir()`, called at the top of both `investigate()` and `resume()` before `_run_pipeline()` — so validation precedes every stage and every Groq call; the LLM client is never constructed for an invalid bundle. `api/errors.py` + `api/app.py` map `InvalidIncidentBundleError` to `400 invalid_incident_bundle`.
  - Containment is verified *before* any evidence file is opened: a canonical evidence path (`logs/application.log` or `metrics/metrics.csv`) that resolves outside the bundle root is reported as `bundle_escapes_root` but is never read or parsed, so escaped content cannot leak into a `400` detail.
  - 98 focused tests in `tests/test_bundle_validator.py` covering all eight required categories (valid bundles, missing files, empty/malformed files, partial evidence, invalid IDs and traversal, actionable errors, validation-before-LLM, no mutation / no `ground_truth.md` access), plus metrics-timestamp contract cases and file-symlink escape cases (including a file-open trace proving escaped content is never read).
  - **Executed locally** (Windows, no database): focused validator tests 92 passed / 6 skipped (symlinks); full offline suite 799 passed / 54 skipped / 1 warning (853 collected); incident validation 51/51; bundle-validator CLI reports `VALID` for all 10 canonical fixtures; `git diff --check` clean. **No CI run for Mission 18 yet**; **PostgreSQL integration not run locally**.
  - **Known residual limitation (accepted):** the bundle is validated before the pipeline re-reads it, so a symlink swapped in between the preflight check and the read is not re-checked (a narrow TOCTOU window). This is documented rather than closed by architectural change.
